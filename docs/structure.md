# File structure

Where everything lives, and where to put new things.

## The tree

```
Zentro-FE/
├── src/
│   ├── main.ts                    Bootstraps the app with appConfig
│   ├── index.html · styles.css    Global entry and the Tailwind @theme token layer
│   │
│   ├── environments/              API origin and build-time flags
│   │
│   └── app/
│       ├── app.ts / app.html      Root shell
│       ├── app.config.ts          Providers: router, HTTP + interceptors, zoneless
│       ├── app.routes.ts          Composes each feature's routes
│       │
│       ├── core/                  Singletons. Instantiated once, app-lifetime.
│       │   ├── auth/                auth.service, auth.store, guards, interceptors
│       │   ├── api/                 api.client + generated/ (never hand-edited)
│       │   ├── config/              Injection tokens for environment values
│       │   ├── layout/              Shell, nav, sidebar
│       │   └── errors/              Global error handling, error envelope types
│       │
│       ├── shared/                Dumb and reusable. Injects nothing.
│       │   ├── ui/                  button, input, modal, avatar, money,
│       │   │                        empty-state, skeleton, badge
│       │   ├── pipes/               money, relative-date, initials
│       │   ├── directives/          autofocus, click-outside
│       │   └── utils/               Pure functions only
│       │
│       └── features/              One folder per domain area
│           ├── auth/                login, register, verify-email, reset
│           ├── groups/              list, detail, create, members, invite
│           ├── expenses/            create/edit, list, detail, split editor
│           ├── settlements/         settle-up flow
│           ├── activity/            feed
│           ├── friends/             friend list, one-on-one expenses
│           └── profile/             profile, preferences
│
├── docs/                          You are here
└── public/                        Static assets served as-is
```

## Inside a feature

Every feature looks the same. Consistency here is worth more than local cleverness:

```
features/groups/
├── groups.routes.ts             The feature's routes, composed into app.routes.ts
├── groups.store.ts              Signals + resources. The feature's state.
├── groups.service.ts            API calls, using generated types
├── group-list/
│   ├── group-list.ts            Smart: injects the store, routed
│   ├── group-list.html
│   └── group-list.spec.ts
├── group-detail/
└── components/                  Dumb components used only by this feature
    └── group-card/
```

Routes live in the feature, so adding a screen doesn't touch a shared file and two people
adding screens don't conflict.

## Where do I put X?

| I'm adding... | It goes in |
|---|---|
| A new screen | `features/<area>/<screen-name>/` + a route in that feature's `.routes.ts` |
| A button, input, modal — anything generic | `shared/ui/` |
| A component only one feature uses | `features/<area>/components/` |
| State two screens in one feature share | That feature's `.store.ts` |
| State two **features** share | `core/` — and think hard about whether it's really shared |
| An API call | The feature's `.service.ts`, using generated types |
| A pure formatting helper | `shared/pipes/` if used in templates, `shared/utils/` otherwise |
| A route guard | `core/auth/guards/` |
| An HTTP interceptor | `core/auth/interceptors/` |
| A color, spacing or type value | Nowhere — use an existing theme token from `styles.css` |
| A decision worth remembering | `docs/adr/` |

## Rules the structure encodes

1. **`features → shared → core`, one direction.** ESLint enforces it.
2. **No feature imports another feature.** When two need the same thing, it moves down a
   layer. This is the boundary that erodes first and takes navigability with it.
3. **`shared/` injects no services.** A shared component takes inputs and emits outputs. If
   it needs a service, it isn't shared — it's a feature component.
4. **`core/` imports nothing from above it.**
5. **`core/api/generated/` is never hand-edited.** It is regenerated by `npm run api:sync`,
   and CI fails if what's committed doesn't match.
6. **Specs live beside the thing they test**, as `*.spec.ts`.

## Naming

| Thing | Convention | Example |
|---|---|---|
| Files | kebab-case | `group-detail.ts` |
| Components | PascalCase class, `z-` selector prefix | `class GroupDetail`, `<z-group-card>` |
| Stores | `<feature>.store.ts` | `groups.store.ts` |
| Signals | The value, not the mechanism | `groups`, not `groupsSignal` |
| Booleans | A predicate | `isLoading`, `hasMembers` |
